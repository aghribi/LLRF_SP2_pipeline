## Keeping results in sync with the pipeline (2026-09-06)

Every quantitative claim in `sections/*.tex` should cite a `\Metric...` macro
from `sections/_generated_macros.tex`, never a hand-typed number. That file is
auto-generated by `code/generate_macros.py` from `analysis/results_manifest/
*.yaml` -- one YAML per pipeline phase, written by that phase's script calling
`utilities.reporting.manifest.save_manifest()` (see that module's docstring).

**Workflow after any pipeline change** (rerun a script, fix a bug, land a new
dataset version): the affected script(s) already end in `save_manifest()`, so
their manifest updates automatically. Then, from `report/`, run:

```
make sync
```

This regenerates `_generated_macros.tex` and runs `code/
check_no_hand_typed_numbers.py`, which fails loudly if any section now
contains a bare number not backed by a macro or an explicit
`% MANUAL: <reason>` trailing comment (for genuine non-result constants like
a reporting-period year). A clean `make sync` is the actual "is the report
still honest" gate -- a successful LaTeX compile only proves the syntax is
valid, not that the numbers are current.

If a script that should produce a citable number doesn't call
`save_manifest()` yet, add the call there (see any `prepare_0*.py` script for
the pattern) rather than hand-typing the number into the report.

## Figure Generation (rewritten 2026-09-06)

Every figure is generated by its own small script in `code/` (`fig_*.py`),
all sharing one style module, `code/plot_style.py` (Okabe-Ito colorblind-safe
palette + distinct markers/linestyles, fonts/widths matched to `main.tex`'s
live `revtex4-2` class, vector PDF output). Run `make figures` to regenerate
all of them, or run one script directly:

```bash
cd report
/pbs/home/a/aghribi/throng_m4cast/environment/env_llrfspiral2/bin/python code/fig_precursor.py
```

The `env_llrfspiral2` environment is required, not the ambient `python3` --
these scripts unpickle trained models (sklearn 1.6.1) and, for
`fig_signal_examples.py`, import `PyPostMortem` directly.

### Figure Specifications
- **Format:** PDF, vector (embedded real glyphs, not bitmapped text)
- **Size:** matches `main.tex`'s live column widths -- single-column 3.404in
  (`SINGLE_COL_WIDTH`), full two-column spread 7.058in (`FULL_WIDTH`)
- **Fonts:** STIXGeneral body text / `stix` mathtext (no Times/CMU font is
  installed in this environment; STIX is the closest available match to
  Computer-Modern-style scientific typesetting), 7-9pt
- **Style:** Okabe-Ito colorblind-safe categorical palette + a distinct
  marker/linestyle per series (never color alone); `cividis`/`PuOr` for
  sequential/diverging plots

### Figure Sources (real, current pipeline data -- not `analysis/outputs/`)

Every `fig_*.py` script's own docstring states its exact data source
precisely. Prefer these over any older `analysis/outputs/*.png` --
those predate the V6 leakage/methodology fixes documented in
`sections/03_system_description.tex`/`04_methodology.tex` and should not be
reused:
- `fig_signal_examples.py` -- raw postmortem files (`PyPostMortem`), one per
  class, run through `prepare_data_cluster_v6.py`'s own `preprocess_signals()`
- `fig_precursor.py` -- `cooked_data_v6/step_05_v6/precursor_detection.pkl`
- `fig_subtype_profiles.py` -- `cooked_data_v6/step_09c_enhanced_subclass/
  enhanced_subclass_full.pkl` + `features_engineered.pkl`
- `fig_shap_lime.py` -- retrains `prepare_10_enhanced_shap_analysis.py`'s own
  per-label (one-vs-rest) models for one representative category
- `fig_confusion_matrix.py` -- `cooked_data_v6/step_08_phase3a_v6/root_cause.pkl`

### Adding a New Figure

Add a new `code/fig_<name>.py` following the existing scripts' pattern:
import `plot_style`, call `apply_style()`, load the real pipeline output
(never re-derive from `analysis/outputs/`), build the plot, and
`savefig_pdf(fig, FIG_DIR / "<name>.pdf")`. Wire it into a section's
`\includegraphics{figures/<name>.pdf}` and add the script to the `figures`
target in `Makefile`.

2. Call function in `main()`:

```python
def main():
    # ... existing figures ...
    generate_my_new_figure()
```

3. Reference in LaTeX:

```latex
\begin{figure}[t]
    \centering
    \includegraphics[width=0.48\textwidth]{figures/subdir/filename.pdf}
    \caption{My figure caption.}
    \label{fig:my_label}
\end{figure}
```

## Article Structure

### Main Sections

1. **Abstract** (250-300 words)
   - Context, problem, methodology, results, impact

2. **Introduction** (~3-4 pages)
   - Background on SPIRAL2 and LLRF systems
   - Problem statement and motivation
   - Key contributions
   - Paper organization

3. **Related Work** (~2-3 pages)
   - Anomaly detection in industrial systems
   - Fault diagnosis in particle accelerators
   - Multi-label classification and root cause analysis
   - Explainability in critical systems

4. **System Description** (~2 pages)
   - SPIRAL2 LLRF system architecture
   - Dataset description (14,231 events)
   - Data quality and preprocessing

5. **Methodology** (~6-7 pages) - CORE CONTRIBUTION
   - 10-phase pipeline architecture
   - Physics-informed feature engineering
   - Detailed description of each phase

6. **Explainability** (~3-4 pages)
   - SHAP feature importance
   - LIME local explanations
   - Physics-informed validation
   - Granger causality analysis

7. **Results** (~4-5 pages)
   - Overall pipeline performance
   - Phase 08: Root cause identification (93.3% accuracy)
   - Phase 09: Fault subtype discovery (21 subtypes)
   - Ablation studies
   - Baseline comparisons

8. **Discussion** (~3 pages)
   - Key findings
   - Practical implications
   - Limitations and challenges
   - Lessons learned

9. **Conclusion** (~1-2 pages)
   - Summary of contributions
   - Future directions

### Appendices

- **Appendix A:** Complete feature set (68 features with mathematical definitions)
- **Appendix B:** Hyperparameter settings for all models
- **Appendix C:** Additional results (extended confusion matrices, learning curves, etc.)
